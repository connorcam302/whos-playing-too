# Dota patch reference refresh

Run `bun run build-items` and `bun run build-heroes` from the repository root with the intended `DATABASE_URL` configured. Bun loads the local environment. These commands regenerate checked-in TypeScript data **and upsert reference rows in the configured database** (including changed names/images); they preserve retired database IDs. They do not deploy the website or update the external scraper.

Both scripts use [OpenDota dotaconstants](https://github.com/odota/dotaconstants) as the historical baseline. Patch-day updates can precede that mirror: the item script overlays Valve's English [item list](https://www.dota2.com/datafeed/itemlist?language=english), including recipes and neutral items. The hero script overlays Valve's live hero details in batches of eight, updating attributes, growth, movement, health/mana, armor, ability lists, talents and numeric ability names. Remaining fields (for example base attack damage, attack point and Captain's Mode eligibility) come from dotaconstants and can lag a new patch. Base health/mana/regen/armor are derived from Valve's level-one totals using the 7.42 attribute rules; revisit those conversions when attribute formulas change. Neither dataset is a historical per-patch stats snapshot.

Generated files are `itemMap.ts`, `heroMap.ts`, `heroData.ts`, `heroAbilities.ts` and `abilityNames.ts` under `src/lib/data`. Generation uses JSON serialization for upstream text and Prettier for stable output, preserves legitimate zero stats, awaits file writes, closes database connections and exits unsuccessfully on refresh failures. Inspect the generated diff before committing; a failure can leave regenerated local files even if database synchronization fails. Legacy facet metadata remains from dotaconstants for historical match rendering; the scripts do not infer historical facet versions.

Patch filters are maintained separately in `src/lib/data/dotaPatchRanges.ts`. Add each numbered release using its release date, keeping entries chronological. **7.42 starts on 18 November 2026**, as confirmed by [Valve's patch notes](https://www.dota2.com/patches/7.42). Bounds follow the existing UTC calendar-day convention: 7.41 ends at 23:59:59 UTC on 17 November and 7.42 is open-ended until the next numbered patch. This deliberately does not distinguish matches before/after the actual release time within that date.

After refreshing, run `bun test tests/dota-reference-data.test.ts`, inspect the diff and run the normal check/build commands. Verify that new item IDs have names/images, historical IDs still resolve, hero stats retain valid zeros and patch ranges do not overlap. Provider availability and a production deployment must be verified separately.
